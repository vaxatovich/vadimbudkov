# SEO и GEO: настройка и проверка

## 1. Основной production-домен — критически важно

Основной production-адрес сайта: `https://vadimbudkov.vercel.app/`. Canonical, sitemap, robots.txt и JSON-LD должны использовать этот домен. Если впоследствии появится собственный домен, обновите эти URL вместе и настройте 301-редирект.

Перед подачей сайта в индекс синхронизируйте:
- `index.html` и `about.html`: `<link rel="canonical">`, `og:url`, `og:image`, идентификаторы `@id` в JSON-LD.
- `sitemap.xml`: абсолютные адреса главной и «Обо мне».
- `robots.txt`: строку `Sitemap:`.
- `llms.txt`: навигационные ссылки (не обязательно для индексации).
- ссылки в README (не влияют на индексацию, но помогают поддержке).

Если обе версии сайта доступны публично, необходимо выбрать одну предпочтительную и по возможности настроить 301-редирект с другой версии. Canonical сам по себе является сигналом, а не гарантией.

## 2. Google Search Console

Google Search Console требует подтверждения владения ресурсом. Без Google-аккаунта владельца и предоставленного Google verification-токена нельзя зарегистрировать и подтвердить сайт.

1. Откройте https://search.google.com/search-console
2. «Добавить ресурс» → «Ресурс с префиксом URL» (URL-prefix).
3. Введите точный адрес основного сайта, включая `https://` и путь (если это GitHub Pages-проект).
4. «HTML-тег» → скопируйте строку `<meta name="google-site-verification" content="...">` и передайте ее для добавления в `<head>` главной страницы. Или используйте Google HTML-файл, который должен размещаться в корне ресурса без изменений.
5. После публикации тега/файла нажмите «Подтвердить» в интерфейсе Google.
6. В разделе «Файлы Sitemap» отправьте `sitemap.xml`.
7. Через «Проверка URL» проверьте главную и `about.html`; при необходимости запросите индексацию.

**Нельзя использовать выдуманный токен подтверждения.**

## 3. Правила обхода

В `robots.txt` отдельные правила `Allow: /` для:
- Googlebot — поиск Google.
- Bingbot — поиск Bing и связанные функции.
- OAI-SearchBot — поиск ChatGPT.

Для остальных краулеров есть `User-agent: *` с `Allow: /`.
Правила обхода не гарантируют индексацию, ранжирование или цитирование в ответах ИИ.

Страница `cases.html` пока содержит `<meta name="robots" content="noindex,follow">`.
Ее **не следует блокировать** в `robots.txt`: робот должен видеть метатег noindex.
Страница отсутствует в `sitemap.xml` до появления содержательных кейсов.

OAI-SearchBot и GPTBot выполняют разные задачи. Разрешение OAI-SearchBot касается поиска ChatGPT и не требует обязательного разрешения GPTBot для обучения моделей.

## 4. Техническая проверка после деплоя

- Страницы открываются без входа в аккаунт и возвращают HTTP 200.
- `/robots.txt` и `/sitemap.xml` возвращают HTTP 200.
- Нет заголовков `X-Robots-Tag: noindex` на главной и «Обо мне».
- CSS и изображения доступны поисковым ботам.
- `canonical` совпадает с основной открывающейся версией страницы.
- JSON-LD корректно парсится, не содержит неподтвержденных результатов и ссылается на основной URL.
- Есть ссылки с главной на «Обо мне», а по готовности кейсов — и на полноценные кейсы.
- Статистика и карьерные достижения представлены видимым HTML-текстом, а не только на изображениях.

## 5. Дополнительно

`llms.txt` — необязательный навигационный файл. Он не является подтвержденным фактором повышения позиций в Google или гарантом цитирования в ChatGPT. Файлы `ai.txt`, `geo.txt` и «специальная SEO-декларация» не требуются.

Если на сайте нет форм, куки-аналитики или сбора данных, не следует добавлять фиктивную политику обработки персональных данных. При добавлении аналитики и форм необходимо оценить требования к уведомлениям/политике для целевой юрисдикции.
